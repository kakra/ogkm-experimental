# Upstream changes in 620.73.04

What NVIDIA changed in the open kernel modules between 620.70.06 and
620.73.04 (tag of 2026-11-18, release notes: "Minor bug fixes and
improvements"), and what it means for the series.

60 files changed. About 195,000 of the changed lines are the regenerated GSP
boot and FMC firmware images for GR100 (Rubin) in
`src/nvidia/generated/g_bindata_kgspGetBinArchive*_GR100.c` and the vGPU
interface header `dev_vgpu_gsp_shared.h`. The remaining source diff is about
2,700 lines. The GSP firmware for Ampere (`gsp_ga10x.bin`) is not part of
this repository; it ships with the user space package of the same release.

## Changes by area

### nvidia-drm

- **Color pipeline (`nvidia-drm-color-pipeline.c`).** With COLOR_PIPELINE
  at 0 (what compositors set for planes without color operations), the
  degamma and TMO state is now only marked changed when it differs from the
  old plane state. Before, every commit made NVKMS reprogram the ILUT and
  TMO. The FP16 pipelines ("NVIDIA FP Full", "NVIDIA FP Lite") no longer
  have an FMT_CTM colorop, since the FMT stage is bypassed for FP16 input;
  the pipeline enum now points at the pipeline's first colorop. A colorop
  that the selected pipeline lacks now counts as bypassed, so state set
  through another pipeline does not stay applied after a switch.
- **ILUT and TMO in modesets (`nvidia-drm-crtc.c`).** The ILUT is sent to
  NVKMS whenever its surface was rebuilt (also for a changed or removed
  CRTC DEGAMMA_LUT). When nothing changed, the request now carries the
  previous ILUT and TMO description instead of leaving it empty: a modeset
  takes every layer field from the request, so an unchanged LUT used to be
  disabled by a modeset.
- **State reset.** The plane, CRTC and connector reset hooks now destroy the
  previous state through the driver's own destroy functions (before, the
  driver-private parts and their blob references leaked on reset).
- **HDCP topology blob (`nvidia-drm-connector.c/.h`).** The blob moved from
  the atomic connector state to `struct nv_drm_connector`. It was
  duplicated into every new connector state, but the NVKMS event replaced
  it only in the current one. The connector now holds the one reference and
  releases it on destruction.
- **Kernel compatibility.** `drm/clients/drm_fbdev_helper.h` (newer DRM
  trees) and `vma_is_hugetlb()` (rename in Linux 7.4) are detected by
  conftest.

### nvidia-modeset (NVKMS)

- **PM lock around direct RM calls from KAPI.** Memory allocation, import
  and export, semaphore surface import and channel event allocation in the
  KAPI (the interface nvidia-drm uses) now take the NVKMS power management
  read lock around their RM calls (`nvkms_lock_pm_from_kapi()`), so they
  can't reach RM while the system is suspended. Relevant for suspend and
  resume with an active compositor; the series' own suspend patches
  (sync FD auto-update, hibernation) do not call these paths with the PM
  lock held.
- **FMT/CSC checks in flips (`nvkms-hw-flip.c`).** A non-identity FMT
  matrix on an FP16 surface is rejected. The CSC00/01/10 checks on layers
  without ICtCp now test the requested state instead of the previous one.

### nvidia (RM)

- **Read-only memory hardening.** New `memdescIsReadOnlyForDevice()` and
  `CliCheckDmaMappingAccess()`. RM no longer writes notifiers, semaphores,
  timestamps or USERD into memory that is mapped read-only for the device
  or the client (`kernel_channel.c`, `method_notification.c`,
  `subdevice_ctrl_event_kernel.c`, `kernel_channel_gv100.c`). Such requests
  now fail with `NV_ERR_INSUFFICIENT_PERMISSIONS`. The new code is wrapped
  in `#if 1`, the pattern NVIDIA uses for security fixes in this
  repository. No public advisory was found for it at the time of writing.
- **SM debugger sessions.** A debugger session checks that a target channel
  belongs to the same client, GPU, device and engine type before acting on
  it (`kernel_sm_debugger_session.c`). Also a security fix.
- **Dependant order in the resource server (`rs_resource.c`).** Dependants
  are inserted ordered by class and handle, so cascading frees run in the
  same order as the old multimap. Possibly relevant to teardown ordering of
  memory objects and their mappings; no direct connection to the VA space
  errors is known.
- **Global context buffers (`kernel_graphics.c`).** Freeing no longer
  returns early when the buffer set is not marked allocated, so partially
  allocated buffers are freed too.
- **TDISP (Rubin, confidential computing).** The registry key
  `RmTdispSkipBar1Validation` is replaced by `RmTdispEnableBar1`. Not used
  on consumer GPUs.

### nvidia-uvm

- **Device P2P VMAs.** `uvm_vm_open_device_p2p()` no longer asserts when the
  backing range is gone or was replaced (after `UVM_FREE` or removal of a
  GPU); it disables the VMA instead. `map_cpu` fails cleanly when the GPU
  was unregistered.
- **HMM.** `VM_SPECIAL` is spelled out as `VM_IO | VM_DONTEXPAND |
  VM_PFNMAP | VM_MIXEDMAP`, and `is_vm_hugetlb_page()` goes through a
  wrapper for its rename to `vma_is_hugetlb()`. In Linux 7.3 `VM_SPECIAL`
  is built from the same four flags, so this is a compatibility change
  without a functional effect there.

### DisplayPort library

- MST: the sink's MAX_UNCOMPRESSED_PIXEL_RATE is checked for every leaf
  sink of the target group, also on the uncompressed retry after DSC was
  declined.
- DP++ ports with an HDMI sink reuse the existing device instead of
  creating a new one; dongle port caps are read based on
  DETAILED_CAP_INFO_AVAILABLE instead of the DPCD revision.
- New regkey `SKIP_DP_LINK_ASSESS`; a WAR for the LG 27GN950 over DP
  tunneling (DSC minimum 9.25 bpp at 4K 160 Hz); the 128b/132b DSC link
  configuration reduction loop was removed; link configuration changes in
  MST are only refused when they are actually committed.

## Relevance for the series

| Topic | Effect of 620.73.04 |
|---|---|
| VA space errors ("can't update VA space", upstream issue [#1364][issue-1364]) | No change in `gpu_vaspace.c`, `virtual_mem.c` or `mapping_list.c` beyond the read-only checks. The read-only RM API lock default is unchanged (`apiLockMask = NVBIT(RS_API_CTRL)`), see [2026-11-07-rm-ro-api-lock](2026-11-07-rm-ro-api-lock.md). |
| Xid 13 with fixed PC | No related change visible in the kernel module source; the fix would have to be in the GSP firmware or user space. |
| VRAM pressure, sysmem fallbacks | No change in the allocation paths. |
| Stalls and latency | No change in the paths the series patches (sysmem free, display ISR, flip). The ILUT/TMO change removes per-flip reprogramming that the series already avoided with patch "fix color pipeline state handling". |
| KWin | Color pipeline and modeset fixes apply to KWin with `COLOR_PIPELINE`; the ILUT/TMO carry-over fixes LUTs being dropped by a modeset. |
| OBS (QSV on the iGPU, obs-vkcapture) | No relevant change. |
| Suspend/resume | KAPI PM lock (above). |

## Rebase of the series

`ogkm/620.70.06` (144 patches) rebased onto 620.73.04 with four conflicts,
all in nvidia-drm and all caused by upstream changes listed above:

1. "add the Broadcast RGB connector property" and "add the underscan
   connector properties": context conflict with the HDCP topology blob
   moving out of the connector state. Resolved by keeping the new fields
   and dropping the old blob duplication.
2. "fix color pipeline state handling" (Tom Englund): its second part
   (only mark degamma/TMO changed when there is something to clear) is now
   upstream in a different form. The upstream version is kept; the patch
   keeps the FMT_CTM blob reference fix and the rejection of a color
   pipeline combined with the CRTC DEGAMMA_LUT or CTM. Commit message
   adjusted.
3. "keep the plane ILUT in sync with the CRTC DEGAMMA_LUT" (ElXreno,
   upstream PR [#1506][pr-1506]): upstream now sends the ILUT whenever it
   was rebuilt, which covers two of the three cases. The patch is reduced
   to rebuilding the ILUT when the plane moves onto another CRTC. Commit
   message adjusted.
4. "only send the HDCP topology uevent when the topology changes": applied
   without a textual conflict but referenced the removed
   `nv_state->hdcp_topology_blob`; adapted to the connector's blob.

No patch became empty. Added from Tom Englund's branch `patches`:
"treat an unmap of an unregistered DMA mapping range as a no-op"
(veldenb, related to upstream issues [#1364][issue-1364] and
[#1453][issue-1453] and to upstream PR [#1483][pr-1483]). Not added: the
two ACPI `_DDC` patches for internal laptop panels (upstream PRs
[#1545][pr-1545] and [#1546][pr-1546]), which only affect systems with an
ACPI-described internal panel.

Result: 145 patches. All objects of all five modules compile against
Linux 7.3.4 (x86_64 defconfig with DRM, HMM and dmem cgroup); final
linking was not checked in that environment. Built against Linux 7.3.5
on the test system and booted on 2026-11-19 without driver warnings in
the kernel log; not tested against the problems the series fixes.
